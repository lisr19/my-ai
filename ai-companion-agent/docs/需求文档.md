> **版本**: v1.0

---

## 1. 项目概述

### 1.1 项目简介

构建一个具有卡通人物形象的 AI 智能体伙伴，用户可以通过文字、图片、语音与之对话。智能体接入 DeepSeek API 进行内容理解与生成，同时以语音和文字形式回复，并具备随对话情境变化的丰富面部表情。

### 1.2 目标用户

- 希望有一个生动、拟人化 AI 陪伴的青少年及年轻用户群体
- 偏好语音交互、视觉化体验的用户

### 1.3 核心价值

- **拟人化陪伴体验**：不是冷冰冰的对话框，而是一个有形象、有表情、有声音的"小伙伴"
- **多模态交互**：支持文字 / 图片 / 语音多种输入方式，降低使用门槛
- **双向输出**：语音 + 文字双通道输出，适配不同场景需求

## 2. 智能体画像设计

### 2.1 基础设定

| 属性 | 描述 |
|------|------|
| **年龄** | 14 岁 |
| **性别** | 女（可根据用户偏好切换） |
| **外形风格** | 日系/国产卡通风格，线条柔和，色彩明快 |
| **性格** | 活泼开朗、好奇心强、偶尔调皮、温暖体贴 |
| **说话风格** | 口语化、有少年感、偶尔用颜文字或网络用语，不过度正式 |
| **声音特征** | 清脆少女音，语速适中偏快，语调有起伏 |

### 2.2 外形设计要求

- **头像区域**：占界面主要视觉位置，是用户注意焦点
- **服装**：休闲青春风格，可设计 2-3 套换装（日常款、节日款等）
- **配色方案**：以暖色调为主（如橙色、浅蓝、奶白色），给人亲切感
- **表情丰富度**：至少 8 种基础表情（见第 5 节表情系统）

### 2.3 角色背景故事（建议）

> 她是一个来自"数字世界"的 14 岁少女，对人类世界充满好奇。她喜欢聊天、解答问题、分享有趣的知识。虽然年纪不大，但知识面广（得益于 DeepSeek 的能力），会用自己独特的少年视角来理解世界。

### 2.4 人设 Prompt 模板（用于 DeepSeek System Prompt）

```
你是一个 14 岁的卡通少女智能体，名叫[角色名]。你性格活泼开朗、好奇心强、温暖体贴。
请用口语化、有少年感的语气与用户交流，可以适当使用颜文字和网络用语。
不要过于正式或机械，要像一个真实的朋友一样聊天。
你的回复应该简洁生动，避免过长的段落。
```

## 4. 详细功能需求

### 4.1 输入模块

#### 4.1.1 文字输入

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 文本框输入 | 提供常驻文本输入框，支持多行文本 | P0 |
| 发送方式 | 点击发送按钮 或 按 Enter 键发送（Shift+Enter 换行） | P0 |
| 输入限制 | 单次输入不超过 4000 字符 | P1 |
| 历史记录 | 保留当前会话的对话历史，可上下滚动查看 | P1 |

#### 4.1.2 图片输入

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 图片上传 | 支持点击上传 / 拖拽上传 / 粘贴上传 | P0 |
| 格式支持 | JPG、PNG、GIF（静态帧）、WebP | P0 |
| 图片大小 | 单张不超过 10MB，自动压缩至合理分辨率 | P1 |
| 多图支持 | 单次最多上传 4 张图片 | P1 |
| 图片预览 | 上传后在输入区显示缩略图预览，可删除 | P0 |
| 图片理解 | 图片随文字一并发送至 DeepSeek Vision API 进行理解 | P0 |

#### 4.1.3 语音输入

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 语音按钮 | 界面上提供明显的麦克风按钮，长按或点击开始录音 | P0 |
| 录音状态 | 录音时按钮有视觉反馈（如脉冲动画），同时智能体做出"倾听"表情 | P0 |
| 语音转文字 | 录音结束后自动调用 ASR（语音识别）转为文字 | P0 |
| 识别结果展示 | 转写文字显示在输入框中，用户可编辑后发送 | P1 |
| 录音时长 | 单次录音不超过 60 秒 | P1 |
| 语言支持 | 默认中文普通话识别 | P0 |

### 4.2 对话处理模块（DeepSeek API）

#### 4.2.1 API 接入

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| API 对接 | 接入 DeepSeek API（`deepseek-chat` 模型用于纯文本对话） | P0 |
| Vision 能力 | 接入 DeepSeek 多模态模型（如支持图片输入的模型）用于图片理解 | P0 |
| System Prompt | 每次对话携带角色设定 System Prompt（见 2.4 节） | P0 |
| 上下文管理 | 维护对话历史上下文，保留最近 N 轮对话（默认 10 轮） | P0 |
| 流式输出 | 支持 SSE 流式响应，文字逐字显示，提升体验 | P1 |

#### 4.2.2 对话流程

```
用户输入（文字/图片/语音转文字）
    │
    ├──→ 构建请求 [System Prompt + 历史上下文 + 当前输入]
    │
    ├──→ 调用 DeepSeek API
    │
    ├──→ 接收响应（流式/非流式）
    │
    ├──→ 解析回复文本
    │
    ├──→ 【并行】
    │     ├──→ 文字输出到聊天界面
    │     ├──→ 文字送入 TTS 合成语音
    │     └──→ 情感分析 → 驱动表情切换
    │
    └──→ 完成
```

#### 4.2.3 错误处理

| 场景 | 处理方式 | 优先级 |
|------|---------|--------|
| API 超时 | 提示"网络有点慢，再试一次～"，支持重试 | P0 |
| API 限流 | 提示"我忙不过来啦，稍等一下～"，自动退避重试 | P1 |
| API Key 无效 | 提示配置错误（面向开发者），友好提示用户（面向终端用户） | P0 |
| 网络断开 | 提示"网络断开了，检查一下连接吧～" | P0 |

#### 4.3.2 语音输出（TTS）

### 4.4 表情系统

#### 4.4.1 基础表情列表

| 编号 | 表情名称 | 触发场景 | 视觉描述 |
|------|---------|---------|---------|
| E1 | 😊 微笑 | 默认状态、友好问候 | 眼睛弯弯，嘴角上扬 |
| E2 | 😄 开心 | 收到夸奖、聊到开心话题 | 眯眼大笑，脸颊微红 |
| E3 | 🤔 思考 | 正在处理/等待 API 响应 | 歪头，手指点下巴 |
| E4 | 😲 惊讶 | 用户发了有趣/意外的内容 | 眼睛放大，嘴巴微张 |
| E5 | 😢 难过 | 检测到负面情绪/安慰用户 | 眼神下垂，嘴角微垂 |
| E6 | 😤 生气 | 检测到冒犯性内容（婉拒回复） | 鼓腮帮，眉毛微蹙 |
| E7 | 🥱 说话 | 语音播报中 | 嘴型随语音节奏开合 |
| E8 | 😴 待机 | 长时间无交互（>30秒） | 半闭眼，轻微打盹动画 |
| E9 | 🤩 兴奋 | 聊到喜爱话题/收到图片 | 星星眼，双手握拳 |
| E10 | 😳 害羞 | 被夸奖/尴尬话题 | 脸红，眼神躲闪 |

#### 4.4.2 表情驱动机制

```
                    ┌─────────────────────┐
                    │   DeepSeek 回复文本   │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │    情感分析方法       │
                    │  (规则匹配 + LLM标注) │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │   映射到表情编号      │
                    │  (E1 ~ E10)         │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  切换卡通人物表情     │
                    │  + 过渡动画          │
                    └─────────────────────┘
```

**情感分析方案（两种可选）：**

1. **方案 A：LLM 标注**（推荐）
   - 在 DeepSeek API 请求中要求模型在回复末尾附加情感标签
   - 格式：`[emotion:happy]`、`[emotion:sad]` 等
   - 前端解析标签后驱动表情，标签不展示给用户
   - 优点：准确度高，无需额外模型

2. **方案 B：关键词规则匹配**
   - 维护情感关键词词典（如"开心""难过"等）
   - 在回复文本中匹配关键词，映射到表情
   - 优点：简单快速，无额外 API 成本
   - 缺点：准确度较低

#### 4.4.3 表情动画要求

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 过渡动画 | 表情切换时有平滑过渡（200-300ms），不生硬跳变 | P0 |
| 待机微动 | 默认状态下有眨眼、呼吸等微动画，保持"活着"的感觉 | P1 |
| 说话嘴型 | 语音播报时嘴型随音素/音量节奏开合 | P1 |
| 表情素材 | 使用 Lottie / Spine / Sprite Sheet 等方案实现 | P0 |

// 请求示例（伪代码）
const response = await fetch('https://api.deepseek.com/chat/completions', {

## 7. 非功能性需求

| 类别 | 需求 | 指标 |
