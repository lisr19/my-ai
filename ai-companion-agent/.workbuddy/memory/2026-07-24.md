## Bug 修复：回车发送后白屏

### 现象
用户在输入框按回车发送消息后，整个页面变白屏。

### 根因
**问题 1：** `DigitalHuman3D` 内部的 `<AudioBars>` 子组件使用了 `useFrame`（R3F Hook），但被渲染在 `<Canvas>` 外面。`useFrame` 必须在 Canvas 内部调用，否则抛 "R3F context not found" 错误，导致整个 React 树卸载。

触发时机：发送消息后 → AI 回复 → `speak()` 调用 → `isSpeaking=true` → `<AudioBars>` 渲染 → useFrame 在外部调用 → 崩溃白屏。

**问题 2：** `useAudioAnalyzer` 用 `useEffect` 监听 `audioRef`（ref 对象），但 ref 不触发 effect 重跑。`audioRef.current` 在 `unlockAudio()` 调用前为 null，导致 audio 元素未注册分析器。

### 修复
1. `DigitalHuman3D.jsx` - `AudioBars` 改用纯 `requestAnimationFrame`（DOM 组件无需 R3F 上下文）
2. `useAudioAnalyzer.js` - 改用 `setTimeout` 轮询检测 `audioRef.current` + 重复 `createMediaElementSource` 容错（捕获 InvalidStateError）

### 学到的教训
- R3F 的 hooks（useFrame / useThree / useLoader）只能在 `<Canvas>` 内使用
- 父组件传给子组件的 ref 引用的 mutability 不会触发 useEffect 重跑
- 涉及 Web Audio API 的重复初始化要捕获 InvalidStateError

## 2.0 角色形象升级 + 口型同步修复

### 问题
1. 用户反馈：原 3D 角色太丑（橙色球体 + 小眼睛 + 怪异头发），像 basic blob
2. 嘴巴 audio 驱动失效 — 看不到嘴巴随说话动作变化

### 重写 DigitalHuman3D.jsx
**新角色设计：Q版（Chibi Style）大头小身体**
- 大圆头（半径 0.98）
- 大眼睛（半径 0.22）配双高光 + 蓝色虹膜
- 小红脸颊（粉色透明圆）
- 桃色双马尾（含蝴蝶结 torus）
- 自然刘海（3束 capsule，不完整覆盖，露脸）
- 极小身体 + 白色连衣裙 + 蓝色裙子
- 红色嘴唇（半径 0.13，能明显看到）

### 修复音频分析
**根因**：AudioContext 在 setTimeout（无用户手势）中被浏览器自动挂起，需要在用户手势中创建。

**改动**：
1. **删除 useAudioAnalyzer.js hook**，把音频分析逻辑合并到 useEdgeTTS.unlockAudio() 里
2. **在用户手势中**：
   - 创建 AudioContext
   - 调用 audioCtx.createMediaElementSource(audio)
   - 调用 audioCtx.resume() 解挂
   - 立即启动 RAF 分析循环（计算 RMS 音量 → amplitudeRef.current）
3. **App.jsx 直接**从 useEdgeTTS 取 amplitudeRef
4. **更明显的嘴型**：mouthSY 从 0.3 (闭) → 2.3 (大张)，保证说话时一定有可见开口

### 验证截图
通过 Playwright 连续截图捕获，lipsync-a (闭) → lipsync-f (开) 的对比证实口型动画工作。

### 学到的教训
- Web Audio API 的 AudioContext 必须在用户手势中创建/恢复（Chrome autoplay policy）
- 把音频分析和 TTS 合并到同一个 hook 比分离更可靠，避免时序问题
- Three.js mesh 越小越难看到动画，要做视觉演示就得把关键元素放大
